## 자동 계산 검증

고정 시드 `20260909`로 각 형질의 실제 문제 생성기를 실행했다. 형질별 4개 가계도 패턴에서 각각 2,500개씩, 총 30,000개 문제와 247,500명의 정답을 검사했다.

검증기는 문제 생성 시 숨겨진 유전자형을 정답으로 사용하지 않는다. 화면에 주어지는 표현형과 부모·자녀 관계만으로 가계도 전체의 가능한 유전자형 배치를 전수 탐색하고, 각 인물의 가능한 후보 집합을 기존 추론기와 비교한다. 별도로 생성에 사용한 유전자형의 표현형 및 부모·자녀 전달 일관성도 검사한다.

| 형질 | 문제 수 | 인물 수 | 정답 후보 불일치 문제 수 | 생성된 유전자형의 유전 관계 오류 |
|---|---:|---:|---:|---:|
| 쌍꺼풀 | 10,000 | 82,500 | 0 | 0 |
| ABO 혈액형 | 10,000 | 82,500 | 0 | 0 |
| 적록 색맹 | 10,000 | 82,500 | 2,120 | 0 |

색맹의 2,120개 문제에서는 각각 한 명의 정답 후보 집합이 틀렸다. 올바른 후보는 `XX'` 하나인데 프로그램은 `XX`, `XX'` 두 후보를 반환했다. 그 결과 정답 버튼 `XX'`는 오답, `?`는 정답으로 처리된다. 표본의 21.2%이며 실제 사용자에게 나타나는 비율을 추정한 수치는 아니다.

표본에서 발견한 조건별 누락:

- 색맹 딸이 있는 정상 어머니: 679건. 딸이 `X'X'`이므로 어머니도 `X'`를 전달해야 한다.
- 색맹 어머니의 정상 딸: 1,441건. 어머니가 `X'X'`이므로 딸은 반드시 `X'`를 물려받는다.

원인: `quiz.js`의 `deduceColorBlindnessValidGenotypes()`는 정상 여성에 대해 색맹 아버지와 색맹 아들만 검사한다. 색맹 어머니, 색맹 딸 조건은 검사하지 않는다.

별도 3세대 고정 사례에서도 실패했다. 정상 외할아버지·외할머니의 정상 딸이 색맹 아들을 낳으면 딸은 보인자이며, 정상 외할아버지는 `X'`를 줄 수 없으므로 외할머니도 보인자다. 현재 로직은 외할머니까지 제약을 전달하지 않는다. 이 사례는 위 무작위 표본의 발생 건수에 포함하지 않았다.

## 실제 브라우저 풀이 검증

로컬 `quiz.html`에서 화면에 표시된 혈액형, 도형 색상·성별 및 가족 관계로 답을 계산하고 실제 입력과 버튼 클릭으로 확인했다.

| 과정 | 결과 |
|---|---|
| ABO 8명 전체 풀이 | `bo` 직접 입력과 나머지 선택 버튼 모두 정답, 점수 8/8 및 만점 모달 확인 |
| 쌍꺼풀 9명 전체 풀이 | `eE` 직접 입력, 확정 유전자형 및 `?` 버튼 모두 정상, 점수 9/9 및 만점 모달 확인 |
| 색맹 8명 풀이 | 올바른 `X'Y`를 입력하려다가 `X'`에서 입력이 잠기는 오류 재현. 나머지 7명은 버튼으로 정답, 최종 7/8 확인 |
| 인물 전환 | 해당 인물 카드와 정답·오답 피드백 전환 확인 |
| 새 문제 / 재도전 / 형질 전환 | 점수 0, 입력 초기화 및 완료 모달 닫힘 확인 |
| 브라우저 오류 로그 | 수집된 페이지 오류 로그 없음 |

색맹 직접 입력 오류는 `renderSelectedPersonCard()`에서 입력 길이가 2 이상이면 즉시 채점하기 때문이다. `X'Y`, `XX'`, `X'X'`를 완성하기 전에 오답 판정 후 입력란이 비활성화된다. ABO에는 이전 수정에서 입력 완료 후 채점하도록 예외를 적용했지만 색맹에는 적용되지 않았다.
